# Day 20 — Full-corpus PyTorch CUDA run

This directory contains the lightweight reproducibility artifacts from the
enhanced Day 20 run. The approximately 23 MB model/optimizer checkpoints remain
under `checkpoints/day20-full/torch/` and are intentionally ignored by Git.

## Configuration

- Device: NVIDIA CUDA (Quadro M2000M, 4 GB)
- Dataset: all 29,000 Multi30k training pairs and all 1,014 validation pairs
- Tokenizer: joint English/German from-scratch BPE, 2,048 tokens, training data only
- Model: pre-norm, 128 dimensions, 4 heads, 3 encoder and decoder layers, 512-dimensional FFN
- Parameters: 1,915,392
- Batch size: 64
- Maximum sequence length: 64 (3 training pairs truncated, 0 validation pairs)
- Epochs: 30
- Optimizer steps: 13,620

| 25 | 11,350 | 2.1507 | 2.3993 | 9,737 |
| 30 | 13,620 | **2.1063** | **2.3910** | 9,706 |

The final epoch is both the latest and best checkpoint. Across the run,
training loss fell by 62.3% and validation loss by 44.0%. Compared with the
earlier 2,000-pair Day 20 run, the best validation loss improved from 3.7800
to 2.3910 and deterministic translations became strongly source-conditioned.

For example, the model consistently learned the sleeping/green-room/sofa
sentence and the boy/headphones/shoulders relationship. The rarer cotton
loading example improved from an unrelated generic caption to the correct
group/truck/loading structure, although its object remains inconsistent.
These samples are diagnostic; formal corpus-level BLEU scoring is scheduled
for Day 23.

Artifacts:

- `tokenizer.json` — exact 2,048-token vocabulary and learned BPE merges.
- `history.jsonl` — exact metrics for all 30 epochs.
- `translations.jsonl` — three deterministic validation samples per epoch.
- `loss_curve.svg` — train/validation loss curve generated by the training CLI.
